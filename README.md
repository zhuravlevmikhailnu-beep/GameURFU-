# 1. Идея
1.1 Жанр

2D платформер с элементами аркады и экшена.

1.2 Игровой мир

Фэнтезийный пиксельный мир: подземелья, пещеры, руины, леса.
Мир разбит на небольшие уровни с препятствиями и врагами.

1.3 Сюжет

Игрок управляет маленьким слаймом, который пытается выбраться из опасного подземелья.
По мере прохождения он становится сильнее и открывает новые способности.

1.4 Персонаж (-и) Враги

Главный герой:

Слайм (может прыгать, делиться, ускоряться)

Враги:

Летающие существа
Шипы (статичные ловушки)
Другие агрессивные слаймы
# 2. Геймплей
2.1 Логика игры
Игрок перемещается по уровню
Избегает препятствий и врагов
Собирает бонусы
Достигает выхода
2.2 Игровые механики
Прыжки
Двойной прыжок (по мере прогресса)
Столкновения (collision detection)
Урон и здоровье
Подбор предметов (например, улучшения)
2.3 Уровни игры
Линейные уровни
Постепенное усложнение
Новые механики на каждом этапе
Финальный уровень с повышенной сложностью
3. Оформление
3.1 Фоны
Пиксельные задники (пещеры, стены, небо)
Параллакс-эффект (для глубины)
3.2 Персонажи (враги)
Простой пиксельный стиль
Анимации (движение, атака, смерть)
3.3 Элементы игры (предметы...)
Монеты / кристаллы
Усиления (ускорение, щит)
Платформы (движущиеся, исчезающие)
3.4 Спрайты
Спрайт-листы для анимации
Разделение на состояния (idle, jump, move)
# 4. Техническая красота
4.1 Игровой движок
MonoGame
4.2 Архитектура классов
Game1 — основной цикл игры
Player — логика игрока
Enemy — базовый класс врагов
Level — управление уровнями
CollisionManager — обработка столкновений
4.3 Композиция MVC
Model: данные объектов (позиция, здоровье)
View: отрисовка спрайтов
Controller: обработка ввода
4.4 Архитектура паттерна и классов
Component-based подход
State pattern (состояния игрока: idle, jump, attack)
Factory (создание врагов)
4.5 Реализация паттерна и классов
Отдельные классы для состояний
Интерфейсы (IEntity, IMovable)
Разделение логики и рендера
# 5. Тестирование
5.1 Тесты
Проверка столкновений
Проверка логики движения
Проверка переходов между уровнями
5.2 Тестирование на удобство и понятность
Удобство управления
Читаемость интерфейса
Баланс сложности
Отсутствие “нечестных” ситуаций
