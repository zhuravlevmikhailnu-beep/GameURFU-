# 1. Идея
1.1 Жанр

 - 2D roguelike / roguelite с видом сверху (top-down shooter)
 - Основной упор: быстрые сессии, случайная генерация уровней, разнообразие оружия.

1.2 Игровой мир

Фантастический мир, состоящий из подземелий (данжей), разбитых на комнаты.
Каждый уровень генерируется процедурно.
Темы уровней:
 - Замок
   
1.3 Сюжет

Игрок — герой, который пытается восстановить баланс мира, нарушенный из-за кражи магического артефакта.
Для этого он проходит через уровни, побеждает врагов и боссов.

1.4 Персонажи и враги

Игрок:
 - Базовый персонаж
 - Характеристики: здоровье, энергия, урон
   
Враги:
 - Ближнего боя
 - Дальнего боя
 - Боссы (в конце уровня)
 # 2. Геймплей
 
2.1 Логика игры
 - Игрок появляется в стартовой комнате
 - Проходит комнаты, уничтожая врагов
 - Получает награды (оружие, улучшения)
 - Переходит на следующий уровень
 - При смерти — начинается новая игра (roguelike элемент)
   
2.2 Игровые механики
 - Передвижение (WASD)
 - Стрельба / атака
 - Уклонение / рывок (dash)
 - Система здоровья и урона
 - Лут (выпадение предметов)
 - Процедурная генерация уровней
   
2.3 Уровни игры
 - Состоят из комнат(Комнаты соединены дверями)
В каждой комнате:
 - Враги
 - Награды
 - В конце уровня босс

# 4. Техническая часть

(“Техническая красота” лучше переименовать — так звучит гораздо серьезнее)

4.1 Игровой движок

Выбранный движок:
 - MonoGame
Обоснование выбора:
 - В детстве играл в эту игру и хотел бы попробовать ее воссоздать 
4.2 Архитектура классов

Основные сущности:
 - GameManager
 - Player
 - Enemy
 - Weapon
 - Level / Room
   
4.3 Архитектурный подход (MVC)
 - Model — данные (статы, состояние)
 - View — отображение (спрайты, UI)
 - Controller — логика управления

4.4 Используемые паттерны
 - Singleton (GameManager)
 - Factory (создание врагов/оружия)
 - Observer (события, UI)
 - State (состояния игрока/врагов)
